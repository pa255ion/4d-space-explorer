Linux, the “Unsafe WebGPU” flag, and security

On Windows, macOS and ChromeOS, current Chrome, Edge and Safari support WebGPU with no setup. On Linux, Chromium-based browsers (Chrome, Brave, Edge) currently only offer it with two flags turned on: #enable-unsafe-webgpu and #enable-vulkan.

The “unsafe” flag is a real security trade-off. It turns on WebGPU where the browser hasn't finished security-reviewing the GPU stack, bypasses the browser's list of GPU drivers known to be unsafe, and exposes experimental GPU features. It applies to every website you visit, not just this one. A malicious page could exploit bugs in the browser's WebGPU code or in your GPU driver to crash the browser or graphics, and in the worst case read memory it shouldn't or escape the browser's GPU sandbox.

  • Safest: use a separate browser instance only for this, started from a terminal with its own profile, and don't browse elsewhere with it, e.g.
    brave-browser --user-data-dir="$HOME/.cache/webgpu-profile" --enable-unsafe-webgpu --enable-features=Vulkan
    (use your browser's own command: google-chrome, chromium, …).
  • Otherwise, turn the flags off again in brave://flags / chrome://flags when you're done.
  • Keep the browser and your GPU drivers up to date either way.

If the game says SOFTWARE RENDERER, WebGPU is running on your CPU, not your GPU (very slow). That usually means the Vulkan flag is off or the browser can't reach your GPU driver: check that brave://gpu / chrome://gpu says “WebGPU: Hardware accelerated”.
