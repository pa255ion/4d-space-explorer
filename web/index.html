Linux, the “Unsafe WebGPU” flag, and security

On Windows, macOS and ChromeOS, current Chrome, Edge and Safari support WebGPU with no setup. On Linux, Chromium-based browsers (Chrome, Brave, Edge) currently only use the GPU for WebGPU with four flags (in chrome://flags or brave://flags):

  • #enable-unsafe-webgpu: Unsafe WebGPU Support → Enabled
  • #enable-vulkan: Vulkan → Enabled
  • #use-angle: Choose ANGLE graphics backend → Vulkan
  • #ignore-gpu-blocklist: Override software rendering list → Enabled

With only some of them, the browser may give no GPU or fall back to a software renderer.

These flags are a real security trade-off. “Unsafe WebGPU” turns on WebGPU where the browser hasn't finished security-reviewing the GPU stack and exposes experimental GPU features; “Override software rendering list” makes the browser use GPU drivers it has blocked as buggy or unsafe. Both apply to every website you visit, not just this one. A malicious page could exploit bugs in the browser's WebGPU code or in your GPU driver to crash the browser or graphics, and in the worst case read memory it shouldn't or escape the browser's GPU sandbox.

  • Safest: use a separate browser instance only for this, started from a terminal with its own profile, and don't browse elsewhere with it, e.g.
    brave-browser --user-data-dir="$HOME/.cache/webgpu-profile" --enable-unsafe-webgpu --enable-features=Vulkan --use-angle=vulkan --ignore-gpu-blocklist
    (use your browser's own command: google-chrome, chromium, brave-origin, …).
  • Otherwise, turn the flags off again in brave://flags / chrome://flags when you're done.
  • Keep the browser and your GPU drivers up to date either way.

If the game says SOFTWARE RENDERER, WebGPU is running on your CPU, not your GPU (very slow). That usually means one of the four flags is missing or the browser can't reach your GPU driver: check that brave://gpu / chrome://gpu says “WebGPU: Hardware accelerated”.
